# ChatGPT Math 26.818.32112 隔离 profile 启动复核

日期：2026-08-22

最终状态：`PASS_ISOLATED_PROFILE_LAUNCH`

诊断修正：`SIGNING_IDENTITY_BLOCKER_WITHDRAWN`

## 1. 测试范围

本轮只对已保留的旧数学副本执行 build 隔离 profile 启动测试。没有停止官方 ChatGPT，没有部署新版，没有修改阶段 E 候选、ASAR entry、候选 hash、LaunchAgent 或 Computer History 配置。

## 2. 第一次隔离方式

首先使用 `CODEX_ELECTRON_USER_DATA_PATH` 指向 build 隔离目录。

结果：

- 进程返回 0。
- 输出“正在现有的浏览器会话中打开”。
- 隔离目录没有产生 profile 文件。

新旧 bootstrap 的静态复核证明，macOS packaged 模式下显式设置该环境变量会启用 `requestSingleInstanceLock()`。官方 ChatGPT 已持有单实例锁，因此该测试进程按 bootstrap 设计主动 `app.exit(0)`。

## 3. 第二次隔离方式

改用既有 companion 工作流使用的 `--user-data-dir=<build-isolated-profile>` 参数。

结果：

- 主进程持续运行约 75 秒。
- Computer Use 可稳定读取完整 ChatGPT/Codex 窗口。
- renderer 成功加载并可见。
- 本地 app-server 成功启动、完成 initialize handshake 并进入 connected。
- 账户查询成功，已认证账户存在。
- 项目和任务列表可见。
- Chromium profile 文件、`SingletonSocket`、`SingletonCookie` 和 `SingletonLock` 均生成在 build 隔离目录。
- 未观察到进程被 AMFI 杀死。

授权观察周期结束后，使用前台中断结束测试主进程。复核确认旧数学副本主进程、renderer、service、app-server、node_repl 和 crashpad 测试进程均已结束。

## 4. 诊断结论

本轮真实运行证明：

- 本地 `Codex Math Local Signing` 身份可以启动完整 ChatGPT/Codex 应用。
- `spctl rejected` 和 AMFI `-423 unknown certificate chain` 不是本机基础运行的硬阻断。
- 之前的 `BLOCKED_SIGNING_IDENTITY_REQUIRED` 不再成立。
- 之前的新旧副本启动失败主要是测试启动方式与单实例/profile 条件错误，而不是 ASAR 四项功能修改或缺少 Apple identity。

## 5. 仍需处理的问题

1. 新版候选 designated requirement 绑定 root 证书，旧副本绑定 leaf 证书；两者不一致。
2. `verify-candidate-app-26.818.32112.mjs` 没有验证 designated requirement，既有报告的“完全一致”结论是错误的。
3. 两个可见主界面同时访问同一任务时，观察到 `already has an active writer` 冲突。这证明不应把双可见主应用作为长期运行形态。
4. 隔离实例中的账户 settings 请求返回 workspace 账户边界错误，但不影响本轮基础窗口、认证、任务列表和 app-server 验收。

## 6. 下一步

不重做阶段 B–E，不改候选 ASAR hash。最小后续是：

1. 用显式 requirement 复制旧副本的 leaf 绑定。
